Safe Restoration Guide

To preserve data integrity and prevent SQLite database corruption, active databases should never be blindly replaced while the server is holding active file locks.

Step-by-Step Restoration Procedure:
  1. Stop the Server: Terminate the running Django development server in your terminal window (press Ctrl + C).
  2. Make a Safety Copy: Rename your active database db.sqlite3 to db.sqlite3.old.
  3. Copy the Backup: Copy your chosen snapshot from the backups/ folder into the project root directory and name it db.sqlite3.
  4. Restart the Server: Run python manage.py runserver in PowerShell.
  5. Verify: Log in to the application and verify your restored students and attendance records.
Security Notice: Backups contain sensitive academy records. Always store downloaded backup copies on a secure private drive and never commit them to public version control.
